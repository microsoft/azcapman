## Goal
Produce a cited, AGENTS.md-compliant requirements doc for rebuilding the Claude Code plugin (`.claude-plugin/plugin.json`) and marketplace (`.claude-plugin/marketplace.json`) surfaces in azcapman, incorporating all previously-verified defects so they are not repeated.

## Why
All prior plugin surfaces were deleted in commit 449cf07 per explicit user instruction. User now wants the requirements re-researched (not blindly restored) before any rebuild, one dedicated pass per harness.

## Known prior findings to verify (not re-derive from zero)
- An explicit `"agents"` array in `.claude-plugin/plugin.json` ALWAYS breaks agent loading (validation-rejected or silently drops to Agents(0)) — must be absent entirely.
- Claude Code discovers agents purely from the `agents/` directory; names them from filename stem, not frontmatter `name:`.
- Symlinks: within-plugin symlinks preserved as relative symlinks in cache; elsewhere-in-marketplace symlinks dereferenced/copied; outside-marketplace symlinks skipped for security (per code.claude.com/docs/en/plugins-reference).
- `git archive` extraction of a skill dir alone leaves symlinks DANGLING when targets point outside the skill root (verified via `git archive HEAD skills/... | tar -tvf -`) — azcapman's `SKILL.md` has 62 pointers outside skill root (24 to docs, 20 to vendor, 17 to scripts).

## Acceptance criteria
1. Confirm (with a live citation, not memory) that the plugin.json `agents` array defect and symlink behavior described above are still accurate as of today.
2. Produce exact required file layout for `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` for azcapman, citing the canonical docs page for each required key.
3. State explicitly what happens to azcapman's vendored `skills/vendor/**` symlink structure on Claude Code plugin install, with a citation.
4. Flag anything that cannot be verified (per AGENTS.md's no-fabrication rule) rather than asserting it.
5. Return the requirements as a self-contained markdown document with inline citations.

## Research subagent result (received)
Status: **research phase complete, one major correction to prior memory.**

- **CORRECTION**: the "`agents` array always breaks loading" claim is **refuted** by current docs (code.claude.com/docs/en/plugins-reference). `agents` is a documented, valid `plugin.json` field (`string|array`) that *replaces* the default `agents/` directory scan when present; omitting it falls back to auto-discovery. Prior 8-probe finding likely reflected an old version bug or malformed value — do not resurrect it.
- Agent naming: uses frontmatter `name:`, not filename stem (filename-stem fallback is documented for **skills**, not agents — another correction).
- Unrecognized/extra `plugin.json` keys confirmed safe at runtime (ignored, only `--strict` validation flags them) — supports a shared cross-harness manifest strategy.
- Symlink 3-tier behavior confirmed verbatim: within-plugin preserved (relative symlink in cache); elsewhere-in-marketplace dereferenced/copied; outside-marketplace skipped for security. `--plugin-dir` installs only get tier 1 (no cross-marketplace dereference).
- **azcapman's ~62 escaping symlinks are SAFE only if the plugin's marketplace `"source"` is the repo root (`"./"`) or `--plugin-dir` points at the repo root** — sibling `docs/`/`vendor/`/`scripts/` are then "elsewhere in marketplace" (dereferenced) or "within plugin dir" (preserved). They **break** (dangling) if source is a `git-subdir` sparse checkout of just the skill subdirectory, or `--plugin-dir` points only at the skill subdir.
- Required plugin.json field: only `name`. Marketplace.json requires `name`, `owner`, `plugins`.
- Plugin agent frontmatter supports `name, description, model, effort, maxTurns, tools, disallowedTools, skills, memory, background, isolation`; explicitly does NOT support `hooks, mcpServers, permissionMode` (security restriction on plugin-shipped agents).

**Action needed before rebuild**: set marketplace plugin `source` to repo root, not a subdirectory pointer, to keep the 62 symlinks intact.
