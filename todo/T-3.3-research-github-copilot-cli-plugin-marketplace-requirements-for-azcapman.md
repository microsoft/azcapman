## Goal
Produce a cited, AGENTS.md-compliant requirements doc for rebuilding the GitHub Copilot CLI plugin (`.github/plugin/plugin.json`) and marketplace (`.github/plugin/marketplace.json`) surfaces in azcapman, incorporating all previously-verified defects.

## Why
All prior plugin surfaces were deleted in commit 449cf07. This is the most repo-specific and highest-confidence harness (prior verified note: [[azcapman-github-copilot-cli-plugin-packaging-five-defects-and-the-marketplace-first-fix]]), but must be re-verified against current live docs before reuse.

## Known prior findings to verify (not re-derive from zero)
- Manifest search order: `.plugin/plugin.json` -> `plugin.json` -> `.github/plugin/plugin.json` -> `.claude-plugin/plugin.json`. Marketplace search order: `marketplace.json` -> `.plugin/marketplace.json` -> `.github/plugin/marketplace.json` -> `.claude-plugin/marketplace.json`.
- Agent files MUST be named `*.agent.md` under `agents/`; use `tools:` frontmatter key, NOT Claude's `skills:` key.
- A project-scope `.github/agents/*.agent.md` file SHADOWS the plugin agent of the same name during local testing (project agents load before plugin agents) and must not exist if a same-named plugin agent is intended to be tested; it never ships via plugin install regardless.
- `.github/plugin/plugin.json` DOES need an explicit `agents` array (opposite of Claude Code, which must NOT have one) — the two manifests cannot be harmonized into one file.
- Direct installs (repo/URL/local-path) are DEPRECATED; only `plugin@marketplace` installs will be supported going forward.
- Validation tool: `gh skill publish --dry-run --fix`.

## Acceptance criteria
1. Re-verify each bullet above against current live docs with an inline citation; flag any that have changed since ~2026-07-31/08-05.
2. Produce exact required file layout for `.github/plugin/plugin.json` and `.github/plugin/marketplace.json` for azcapman.
3. State what happens to azcapman's vendored `skills/vendor/**` symlink structure on Copilot CLI plugin install, with a citation.
4. Flag anything unverifiable rather than asserting it.
5. Return the requirements as a self-contained markdown document with inline citations.

## Research subagent result (received)
Status: **research phase complete, 6/7 prior findings confirmed, 2 corrected/refuted.**

- Manifest search orders (plugin and marketplace 4-path lists) — CONFIRMED verbatim, citing cli-plugin-reference#file-locations.
- `*.agent.md`/`agents/`/`tools:` frontmatter — CONFIRMED.
- `.github/agents/` shadowing behavior — CONFIRMED, including the corollary that shadow files never ship via plugin install (project config only overrides locally, never bundled).
- **CORRECTION**: `agents` field in `plugin.json` is **optional** (default `"agents/"`), not "required, opposite of Claude Code." No documented prohibition against including it — the earlier claim of an unbridgeable Claude/Copilot manifest split is not supported by current docs.
- **REFUTED (unverifiable)**: "direct installs are being deprecated" — current docs still list direct/local/URL install as fully supported with no deprecation notice. Explicitly downgraded to unverified; do not assert.
- **CORRECTION**: `gh skill publish --dry-run --fix` is not a documented combined invocation — docs show `--dry-run` and `--fix` as separate flags used independently.
- **Symlinks: UNRESOLVED**, same as Codex/SRE Agent. No docs.github.com page (6 checked) mentions symlink handling during plugin install/caching. Structural reasoning (git-clone-based caching into `~/.copilot/installed-plugins/...`) suggests azcapman's ~62 escaping symlinks would likely go dangling on a marketplace install, but this is inference, not a citable guarantee.
- New file-layout detail: SKILL.md requires `name` + `description`; optional `license`, `allowed-tools`.

**Net effect across all 4 harnesses**: symlink safety is either unresolved or conditional everywhere — no harness has a documented guarantee for azcapman's current escaping-symlink structure.
